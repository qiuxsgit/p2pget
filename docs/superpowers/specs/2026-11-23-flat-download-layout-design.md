# 下载目录扁平化：去掉任务哈希子目录

## 背景与目的

现在每个任务保存在 `downloads/<协议>-<hash>/` 下。v2 / 混合 BT 单文件种子还会多出一层
同名目录（`bt-<hash>/xxx.iso/xxx.iso`），用户会把这个目录当成文件。
用户希望下载结果就是文件本身：直接放在下载根目录，遇到同名时提示，不再靠哈希子目录防覆盖。

## 目标

- BT 单文件种子（v1、v2、混合）：`downloads/<文件名>`。
- BT 多文件种子：`downloads/<种子名>/<文件路径>`。
- ED2K：`downloads/<文件名>`。
- 同名文件已存在、且不属于本任务时：列出冲突路径，退出，不写入任何下载数据。
- 续传规则不变：同一链接 + 同一下载根目录。

## 非目标

- 不兼容、不迁移旧布局（`<协议>-<hash>/`）下的数据。
- 不做下载前的文件预览与选择（另行讨论）。
- 重名时不提供覆盖或改名选项，只提示并退出。

## 方案

考虑过的做法：
- 状态放系统缓存目录：续传与下载目录脱钩，换 `--dir` 或移动目录后状态和文件对不上。不选。
- 状态放文件旁（`xxx.iso.p2pget/`）：下载目录出现可见杂项目录，违背目的。不选。
- **选定：** 状态集中在 `downloads/.p2pget/<协议>-<hash>/`，用“已认领”标记区分续传和重名。

## 设计

**状态目录。** `stateDir = <Dir>/.p2pget/<kind>-<id>/`，内容与现在的 `.p2pget` 相同
（`download.lock`、`link.txt`、`metadata.torrent`、`ed2k.json`、`identity.pem`、`nodes.dat`），
另加标记文件 `claimed`。任务锁仍在状态目录内。

**重名判定。** 对本任务的每个目标文件路径：
- 本任务 `claimed` 存在：视为续传，已有文件属于本任务。
- `claimed` 不存在且目标路径已存在（文件、目录或符号链接）：冲突。
- 多文件种子只判断文件路径；`<种子名>/` 目录已存在本身不算冲突。
  目标路径上的中间目录若是已存在的普通文件，也算冲突。

冲突时一次性列出全部冲突路径并退出（非零退出码），不写 `claimed`、不打开存储。

**认领。** 检查与写 `claimed` 在 `<Dir>/.p2pget/claim.lock` 文件锁内完成，
防止两个终端里不同任务的同名文件同时通过检查。写 `claimed` 后释放该锁。

**检查时机。**
- BT：已有 `DeferStorageOpen`。在 `Progress()` 拿到种子信息、校验通过之后，
  `OpenStorage` 之前做检查与认领。
- ED2K：文件名来自链接，在 `ed2k.New` 创建传输之前做检查与认领。

**BT 路径。** 存储 `ClientBaseDir` 设为 `<Dir>`，自定义 `FilePathMaker`：
- 单文件：种子只有一个文件，且其 `BestPath()` 为空（v1）或等于 `[]string{info.BestName()}`
  （v2 / 混合）。返回 `info.BestName()`。不能用 `Info.IsDir()`：v2 时恒为 true。
- 其他：`BestName()`（非 `metainfo.NoName` 时）拼 `BestPath()`，与库默认一致。
重名检查使用同一函数计算的路径，保证检查的就是将写入的路径。

**ED2K 路径。** `target = <Dir>/<req.Name>`。保留现有“目标存在但不是普通文件则拒绝”的检查。

**提示文字。** 启动时“保存目录”显示下载根目录；完成时显示实际文件路径
（单文件为文件路径，多文件为 `<Dir>/<种子名>`）。

## 测试

- 路径规则单元测试：v1 单文件、v2/混合单文件、多文件。
- 重名：目标已存在且无 `claimed` 时报冲突，且未写入数据、未创建 `claimed`。
- 续传：有 `claimed` 时已有文件不算冲突。
- 冲突退出后再次运行仍报冲突（不会因状态目录已存在被误判为续传）。
- 更新 `internal/download/transfer_test.go` 中 BT、ED2K 的路径断言。
